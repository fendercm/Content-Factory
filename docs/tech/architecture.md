# Архитектура

## Процессы

```
┌──────────────────────┐   HTTP (localhost:5000)   ┌────────────────────────────┐
│ admin_panel.html     │ ────────────────────────▶ │ utils/api_server.py (Flask)│
│ (браузер, vanilla JS)│ ◀──── JSON / видео ─────── │  • читает pipeline.db       │
└──────────────────────┘                           │  • правит config/series     │
                                                   │  • запускает задачи ↓       │
                                                   └──────────────┬─────────────┘
                                   subprocess (лог → logs/jobs/<id>.log)
              ┌──────────────────────┬──────────────────┬─────────┴───────────┬──────────────────┐
              ▼                      ▼                  ▼                     ▼                  ▼
   main.py --format series   scripts/script_lab.py  scripts/order_run.py  scheduler.py   agents/analytics_agent.py
   (сборка/выпуск серии)     (сценарии текстом)     (Студия: заказ)       (расписание)   (статистика Zernio)
              │
              ▼
   agents/* ──▶ внешние сервисы: Gemini (LLM, TTS, vision) · KIE (LLM-сценаристы, Nano Banana, Wan,
                Kling Avatar) · Zernio (публикация, статистика) · Telegram · VK · Pexels · Whisper (локально)
```

- **Панель** не делает тяжёлой работы сама: каждое действие — фоновая задача, отдельный процесс
  Python со своим логом. Сервер следит за процессами и хранит список задач в `logs/jobs/jobs.json`.
- **Планировщик** (`scheduler.py`) — долгоживущий процесс; раз в цикл перечитывает расписания сериалов
  из `config/series/*.json` и пишет пульс в `logs/scheduler.heartbeat` (панель по нему видит, жив ли он).
- **Состояние** — один файл SQLite `pipeline.db` (см. [data.md](data.md)) плюс файлы в `output/`.

## Слои

| Слой | Модули | Роль |
|---|---|---|
| Оркестрация | `main.py`, `scheduler.py`, `scripts/order_run.py` | порядок шагов, повторы, статусы, алерты |
| Сценарий | `anthology_agent`, `order_agent`, `script_writer`, `story_agent` | кейсы, завязки, сценарии, раскадровка |
| Контроль содержания | `safety_agent`, `topic_filter`, `fact_checker` | стоп-темы, дубли, факты (fail-closed) |
| Голос | `dialogue_voice` (сериал/заказы), `voice_agent` (ролики) | Gemini TTS по ролям, тайминги Whisper |
| Картинка | `scene_agent`, `lipsync_agent`, `visual_agent`, `image_agent`, `entity_visuals` | кадры, анимация, говорящие лица, сток |
| Монтаж | `series_assembly`, `assembly_agent`, `subtitle_agent`, `music_agent` | таймлайн, субтитры ASS, звук, музыка |
| Проверка | `series_qa`, `qa_agent`, `quality_scorer` | синхрон, речь, голоса, громкость, кадры, формат, оценка |
| Выпуск | `publisher_agent`, `vk_publisher`, `notify_agent`, `analytics_agent` | Zernio, VK, Telegram, статистика |
| Инфраструктура | `utils/*` | LLM-цепочка, KIE, гейт провайдеров, FFmpeg, загрузки, логи, расходы |

## Поток сериала (кратко)

```
кейс/завязка → сценарий (реплики + [эмоции]) → safety → раскадровка
  → ОЗВУЧКА (первой: бесплатная, может упереться в квоту — до платных шагов)
  → кадры Nano Banana + анимация Wan ∥ музыка
  → липсинк ключевых реплик (Kling Avatar)
  → субтитры по словам → монтаж (видео; звук отдельным проходом)
  → Series QA (синхрон, речь, голоса, субтитры, громкость, кадры, липсинк)
  → оценка кадров (vision) → ffprobe QA → очередь → публикация по кнопке/расписанию
```

Подробно — [series.md](series.md). Студия использует те же кирпичи — [studio.md](studio.md).

## Принципы, которые держат систему

1. **Сначала дешёвое и хрупкое, потом платное.** Озвучка (бесплатный Gemini TTS с дневной квотой)
   идёт до кадров KIE: если голоса нет, деньги не тратятся.
2. **Fail-closed гейты.** Safety, фильтр тем и факт-чекер при недоступности LLM не пропускают контент;
   Series QA при браке не пускает эпизод в очередь. Оценка `quality_scorer` при сбое → `skipped`
   (не блокирует), при низком балле → блокирует.
3. **Одна попытка публикации.** `POST /posts` в Zernio не повторяется, чтобы не было дублей.
4. **Повторы там, где сбои временные.** Шаги пайплайна — до 3 попыток; задачи KIE — повтор при 5xx,
   «try again», обрыве сети (липсинк и анимация — до 2 повторов, кадры — 1).
5. **Отключение провайдера на лету.** Исчерпанная квота/402/401 → `providers.mark_dead()` до конца
   процесса; цепочка идёт к следующему провайдеру без спама повторами.
6. **Ничего не теряется на диске.** Загрузки — через `.part` + переименование; всё оплаченное
   (кадры, клипы, липсинк) лежит в папке запуска и переиспользуется при «доделке» (`--resume`).
7. **dry-run ничего не пишет** в состояние (темы, эпизоды, лор).

## Каталоги

```
main.py, scheduler.py          оркестратор и планировщик
agents/                        агенты (один модуль — одна роль)
utils/                         инфраструктура и сервер панели (api_server.py)
scripts/                       служебные команды (лаборатория, очередь, заказы, бенчмарки)
config/series/<id>.json        сериал; config/series/scripts/ — сценарии для производства
assets/series/<id>/            референс героини, кандидаты портретов; assets/music, assets/sfx
output/series/<run_id>/        всё для одного эпизода (кадры, клипы, озвучка, субтитры)
output/video/                  финальные ролики (+ _segments/ — промежуточный монтаж)
output/orders/<id>/            заказы Студии (order.json, files/, build/, итоговый mp4)
output/script_lab/             результаты лаборатории
logs/                          логи пайплайна, logs/jobs/ — задачи панели
docs/                          документация, финмодели
tests/                         pytest
```
