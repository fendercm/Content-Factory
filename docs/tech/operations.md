# Эксплуатация

## Запуск

| Что | Как |
|---|---|
| Панель | `start.bat` или `py -X utf8 utils/api_server.py` → http://localhost:5000 |
| Планировщик | кнопка «Запустить планировщик» на «Обзоре» или `py scheduler.py`; работает, пока включён компьютер |
| Сборка серии в очередь | панель «Эпизоды» → «Собрать в очередь» или `main.py --format series --prepare N` |
| Выпуск серии | панель «Выпустить следующий сейчас» или `main.py --format series --publish-next` |
| Заказ | панель «Студия» |

На Windows для консоли нужна UTF-8: запускайте Python с `-X utf8` (панель так и делает для задач).
FFmpeg должен быть в `PATH` (в Git Bash: `export PATH="/c/Users/<user>/AppData/Local/Microsoft/WinGet/Links:$PATH"`).

## Расписание (`scheduler.py`)

| Время | Задача |
|---|---|
| `schedule.time` каждого сериала с `enabled: true` | `main.py --format series --series <id> --publish-next` |
| 09:00, 14:00, 20:00 | ролики по нишам (если не `SCHEDULER_MODE=series`) |
| 21:00 | сводка за день в Telegram |
| 08:30 | статистика роликов (`analytics_agent`: YouTube Data API + Zernio) |
| 04:00 | уборка диска (`housekeeping`) |

Расписания сериалов перечитываются каждый цикл — перезапуск после правки в панели не нужен.

- **Автозапуск:** панель при старте сама запускает планировщик, если у какого-то сериала включено
  расписание. Планировщик запускается отвязанным от панели (`DETACHED_PROCESS` + breakaway из job-объекта):
  закрытие панели его не останавливает (2026-10-22 он погиб вместе с панелью и серия не вышла).
- **Один экземпляр:** если пульс моложе 90 с, второй планировщик сразу завершается.
- **Догон:** при старте, если время сегодняшнего выпуска прошло, серия сегодня не выходила и в очереди
  есть готовая — выпуск сразу (`catch_up_series`). Сам `schedule` пропущенное не догоняет.
- Компьютер должен быть включён и не спать в момент выпуска (или планировщик догонит при следующем старте).
Пульс `logs/scheduler.heartbeat` раз в 30 с; панель считает планировщик живым, если пульсу < 120 с.
Если очередь пуста, выпуск не происходит и приходит алерт «подготовьте эпизоды».

## Логи и наблюдение

- `logs/*.log` — общий журнал (страница «Журнал»); `logs/jobs/<id>.log` — каждая задача панели.
- `pipeline_state` — этапы каждого запуска (страница «Обзор» / «Эпизоды» → «Последние сборки»).
- Telegram: ошибки после всех повторов, падение пайплайна, карточка готовой серии, ролик для ручных площадок.
- Секреты в логах, ошибках и Telegram маскируются (`utils/log_redact.py`).

## Тесты

```bash
py -X utf8 -m pytest -q
```

~205 тестов, ~15–35 с, без сети и платных вызовов. `tests/conftest.py` обнуляет ключи с побочными
эффектами (Telegram, Zernio, VK). Обвязки, которые делают `import main`/`import utils.api_server`,
запускаются отдельным процессом и обнуляют ключи сами: в Windows пустая переменная окружения не
передаётся дочернему процессу, а импорт `api_server` в процесс pytest ломает его вывод.

## Типовые сбои

| Симптом | Причина | Что делать |
|---|---|---|
| `User location is not supported for the API use` (Gemini), Telegram `ConnectTimeout` | нет доступа к Google/Telegram из сети (выключен VPN) | включить VPN и перезапустить сборку; упавшая на safety сборка денег не тратит |
| «все провайдеры недоступны» на safety | то же; safety fail-closed | то же |
| Gemini TTS `429`/квота | дневная квота модели исчерпана | цепочка сама идёт к следующей модели TTS; при `voice_fallback: none` эпизод встанет до платных кадров — повторить завтра или после смены ключа |
| «дубль N не принят: лишние слова …» | TTS прочитал пометку вслух | автоматически ещё дубль (до 3); пометки-действия отсекаются `_voice_cue` |
| «переозвучиваю по репликам» | 3 дубля не приняты | голос будет ровнее (без эмоций) — лучше остановить сборку до кадров и поправить пометки в сценарии |
| KIE `500 internal error, please try again later` | сбой у KIE/Kling (чаще липсинк) | автоматические повторы; если всё равно не вышло — статичный кадр |
| KIE `402 Credits insufficient` | кончились кредиты | пополнить; провайдер выключается до конца процесса |
| «на KIE $… а эпизод ≈ $… — пополните баланс» | баланса меньше оценки эпизода (+30 %) | пополнить и собрать заново; денег не потрачено |
| «лимит $… исчерпан» в лаборатории | прогон дошёл до `--max-usd` | готовые сценарии сохранены; повторить недописанные с новым лимитом |
| Series QA «голос сдвинут…» | рассинхрон звука в монтаже (или шум в тихом месте) | проверка требует подтверждения соседним окном; при настоящем сдвиге — пересобрать |
| Панель «Нет связи» | сервер не запущен | `start.bat` |
| Задача `lost` | сервер перезапускался во время задачи | проверить её лог; при необходимости «Доделать» |

## Деньги

- KIE — пополняемый баланс, видно в шапке панели; 200 кредитов = $1. Расход по запускам — таблица `costs`
  (страница «Аналитика» показывает цену серии).
- Gemini, Whisper, FFmpeg, edge-tts, Pexels — бесплатно. Zernio — подписка.
- Себестоимость: серия $0.8–1.7, заказ 30 с ≈ $1–1.5.
- Незаметно не тратится: сборка серии сверяет баланс KIE с оценкой эпизода до первых платных шагов и
  останавливается с алертом, если не хватает ([series.md](series.md#себестоимость-kie-200-кр--1));
  лаборатория пишет траты под своим `run_id` `lab_<время>`, печатает сумму и останавливается на
  `--max-usd` (панель: `max_usd`). Суммы прогонов — `SELECT run_id, SUM(total_usd) FROM costs GROUP BY run_id`.

## Безопасность и репозиторий

- `.env` в `.gitignore`; секреты не печатаются в логи. Перед любым `git push` — ротация ключей и чистка
  истории (решение автора после аудита 2026-10-18; до этого push не делать).
- Панель — только localhost, если не задан `ADMIN_TOKEN` ([admin_panel.md](admin_panel.md#безопасность)).
- Публикация и сборка — только по явному действию автора или по расписанию, которое автор включил.

## Развёртывание с нуля

1. Python 3.13, `pip install -r requirements.txt`, FFmpeg в `PATH`.
2. `.env` по [configuration.md](configuration.md) (не забыть `BUDGET_ALLOW=kie_series`,
   `ZERNIO_ACCOUNT_ID_<СЕРИАЛ>` и аккаунты площадок).
3. Перенести `pipeline.db`, `config/series/`, `assets/series/` (референсы героинь), `assets/music/`.
4. `py -X utf8 -m pytest -q`, затем `start.bat`.

## Статистика роликов

`agents/analytics_agent.py` (по расписанию в 08:30, вручную `py -X utf8 agents/analytics_agent.py --days 7`):

- Посты берутся из Zernio `GET /posts?accountId=ZERNIO_ACCOUNT_ID`.
- YouTube: просмотры, лайки и комментарии — YouTube Data API `videos.list?part=statistics` по
  `platformPostId` (ключ `YOUTUBE_API_KEY`, 1 единица квоты на 50 роликов). Это живые публичные счётчики.
- Остальные площадки (и YouTube без ключа) — Zernio `GET /analytics?postId=…`. Пока Zernio не
  синхронизировал статистику с площадкой, он отвечает 202 и нулями с `syncStatus: "pending"`; такие
  нули считаются «нет данных» и прежние цифры в `performance` не затирают. Эндпоинта
  `/posts/{id}/analytics` у Zernio нет; раньше агент обращался к нему, получал 404 и писал нули.
- Удержание и время просмотра Data API не отдаёт. Источники: Zernio `/analytics/youtube/daily-views` и
  `/analytics/youtube/video-retention` (данные с задержкой ~3 дня, общая дневная квота YouTube Analytics
  у Zernio бывает исчерпана) или YouTube Analytics API с OAuth владельца канала.
