# Сериал-антология

Формат: каждая серия — законченная история одного клиента психолога Веры Соколовой («Кабинет 7»).
Серия ≈ 55–65 с, 9:16, 8–12 реплик. Движок не привязан к психологу: героиня, профессия и место
действия — параметры конфига, новые сериалы создаются из панели ([admin_panel.md](admin_panel.md)).

## Конфиг сериала — `config/series/<id>.json`

| Поле | Назначение |
|---|---|
| `id`, `name`, `format`, `logline`, `season_arc`, `disclaimer` | паспорт и «библия» для сценариста; `disclaimer` идёт в описание поста |
| `heroine.role` | роль в сценарии капсом (`ВЕРА`) — по ней разбираются реплики, голос, кадры, субтитры |
| `heroine.name`, `profession`, `setting`, `bio`, `voice_ru` | подставляются в промпты (`hero_fields`) |
| `heroine.visual_en`, `heroine.reference` | внешность для кадров и путь к референс-портрету |
| `heroine.gemini_voice`, `edge_voice`, `intro` | голос Gemini TTS, запасной голос edge-tts (`голос@сдвигHz`), подпись при первом появлении |
| `voices` | голоса клиента (`client_female`/`client_male`) и рассказчика |
| `location_en`, `style_en` | место и стиль картинки (английский — для Nano Banana) |
| `tts_mode` | `dialogue` — сцена одним запросом multi-speaker TTS; иначе — по репликам |
| `voice_fallback` | `none` — без Gemini эпизод останавливается (edge-tts звучит плохо); `edge` — запасной голос |
| `tts_direction` | режиссура озвучки (вступление к запросу TTS, вслух не читается) |
| `words_min/max`, `lines_min/max` | рамки сценария (kabinet7: 100–125 слов, 10–12 реплик) |
| `audience` | кто зритель — уходит в библию сериала (сценарист) и в промпт критика |
| `animated_key`, `animated_simple` | сколько кадров оживлять Kling 3.0 / Wan 2.6 Flash (сейчас 0 / 3) |
| `lipsync_lines` | `key` — липсинк первой, поворотной и финальной реплики; иначе выключен |
| `voice_tempo` | ускорение озвучки без смены высоты (сейчас 1.15; по умолчанию 1.0) |
| `max_still` | смена крупности: статичный кадр дольше стольких секунд режется, наезд чередуется (сейчас 3.0; нет — выкл.) |
| `hook_question` | `true` — вопрос-крючок вверху кадра до поворота (у kabinet7 выключен: автор забраковал) |
| `subtitle_colors` | цвета субтитров (`hero`, `client`, `РАССКАЗЧИК`), ASS-формат `&HAABBGGRR&` |
| `hashtags`, `also_publish`, `manual_publish` | публикация (см. ниже) |
| `schedule` | `{enabled, time "HH:MM", platform}` — ежедневный выпуск планировщиком |

## Сценарии

### Лаборатория (текст без видео) — `scripts/script_lab.py`

Варианты сценариев пишутся «вслепую» (буквы A, B, …; какая модель писала — в `<время>_key.json`) и
сохраняются в `output/script_lab/<YYYYMMDD_HHMM>.{md,json}`. Режимы:

| Режим | Команда / панель | Что происходит |
|---|---|---|
| Кейсы | `script_lab.py --n 4 [--same]` | `propose_cases` → `write_episode` для каждого кейса |
| По идее автора | `--idea "..."` / поле «Идея» в лаборатории | кейсы строятся на замысле автора |
| Завязки (v2) | `--pitches` / «Завязки серий» | модель пишет питчи; автор ставит 👍/👎 — отметки подмешиваются в следующие запросы как «вкус автора» (`lab_pitches`) |
| Из завязок (v2) | `--from-pitches 12,8,7` | история прозой с открытиями → диалог по тактам → критик по чек-листу (другая модель) сам правит текст, до трёх кругов; в результате видны оценка, замечания и реплика ухода |

**Траты прогона.** У каждого прогона свой `run_id` `lab_<время>` в `costs`; в конце печатается сумма в $,
она же — в `<время>.json` под служебным ключом `"_run"` (`run_id`, `cost_usd`, `max_usd`, `limit_hit`;
панель его не показывает как вариант, а `/api/lab` отдаёт `cost_usd`). `--max-usd X` (панель: `max_usd`
у задач `lab`/`pitches`, 0–50): когда траты прогона дошли до X, новые вызовы LLM не стартуют
(`kie_client.set_spend_limit`); сценарии, которым не хватило денег (в том числе на критика), получают
ошибку «лимит» — черновик остаётся в json, завязка не помечается использованной; готовые сохраняются.
Вызовы, уже ушедшие в KIE, доживают — перерасход возможен на их стоимость (сценарий ≈ $0.02–0.15).

Сценарист — `tier="premium"` LLM-цепочки: KIE Gemini 4 Argon → GPT-6 Astra → бесплатные Gemini
(выбор моделей — слепой тест `scripts/model_bakeoff.py`).

**Ритм открытий (с 2026-10-23).** В YouTube Studio 77 % зрителей досматривали начало, но в среднем
смотрели ~27 с из 60+: первая реплика выдавала тайну целиком, дальше было нечего ждать. Поэтому:
- история (`develop_story`) раскладывается на пять открытий в порядке, в котором их узнаёт зритель
  (`reveals`), и они идут в промпт диалога;
- такты: первая реплика — странный поступок без объяснения, дальше каждые 20–25 слов (8–10 с) новое
  открытие, поворот понятен с первого прослушивания, финал — ясный поступок;
- рамки kabinet7: 100–125 слов, 10–12 реплик (≈ 45–52 с с темпом ×1.15). В лаборатории длина — не брак
  (`_lab_problems`): Argon стабильно пишет 134–146 слов, и оплаченные сценарии выбрасывались; сокращает критик.

**Критик** (`critique_episode`, `tier="critic"`): GPT-6 Astra через KIE → Claude Fable 5 → бесплатные
(`SERIES_CRITIC_MODEL/FALLBACK`) — другое семейство, чем сценарист Argon; Astra вдвое дешевле Claude ($0.04 против $0.09 за оценку). Знает аудиторию сериала
(`audience` в конфиге, по умолчанию «взрослые 30+»), проверяет 10 пунктов (`_CRITIC_CHECKS`, в том числе
`reveals` и понятность поворота), ставит «досмотрит» 1–10 и называет реплику, где зритель уйдёт
(`drop_line`). Принят без правок — 8+ и все пункты.

**Правки вносит сам критик** (`edit=True`, `_CRITIC_EDIT`): тем же вызовом он возвращает сценарий со своими
заменами (поле `script`), до 3 кругов; правка, сломавшая роли или давшая повтор, отбрасывается, в результат
идёт лучшая версия по `_review_rank`: оценка минус число проваленных пунктов (8 с двумя провалами
хуже 7 без провалов), при равенстве — меньше провалов. `parse_screenplay` понимает ответ критика с номерами
реплик («3. ВЕРА: …»), `**РОЛЬ:**`, экранированными `
` и сценарий списком строк. Раньше сценарист переписывал по пересказу замечаний и чинил одно, ломая другое
(оценки 6 → 5 → 6 → 6, 2026-10-23). Оговорка: на следующем круге Astra оценивает текст со своими же правками.

### Требования к сценарию (бриф «исповедь», `anthology_agent._EPISODE_TASK`)

Клиент рассказывает, героиня говорит мало (3–4 короткие реплики, ≥ 25 % реплик), называет клиента по
имени в первых 4 репликах. Формат строки: `РОЛЬ: [как сказать] реплика`. Пометка в скобках — режиссура
для голоса, вслух не читается.

Автоматические проверки `write_episode`:
- `validate_episode` — роли, доля героини, длина серии подряд одного говорящего (≤ 4), слова;
- `copied_from_brief` — 4-граммы, списанные из примеров брифа;
- `repeated_phrase` — повторы внутри серии;
- `polish_episode` — редакторский проход (сохраняет пометки);
- `roles_mixed` — LLM-проверка, не перепутаны ли реплики героини и клиента.

### Сценарии для производства — `config/series/scripts/<id>_<slug>.json`

`{"title", "case": {client_name, age, gender, occupation, signature_detail, ...}, "lines": [{role, text, emotion?}],
"question"?}` — `question` задаёт вопрос-крючок вручную (иначе его пишет модель).
Сохраняются из панели («В производство», редактор) или вручную. Сборка по файлу:

```bash
py main.py --format series --series kabinet7 --niche "психология" --script config/series/scripts/kabinet7_bublik.json
```

## Сборка эпизода — `main.run_series_pipeline`

Шаги пишутся в `pipeline_state` (видны в панели как этапы) и повторяются при сбое (до 3 раз).

| Шаг | Модуль | Что делает |
|---|---|---|
| `anthology_cases` → `topic_filter` → `anthology_episode` | `anthology_agent` | кейсы (тренды ниши — как вдохновение), фильтр тем, сценарий; при `--script` — берётся файл |
| `safety_agent` | `safety_agent` | стоп-категории; недоступность LLM = брак (fail-closed) |
| `anthology_shots` | `anthology_agent.plan_shots` | раскадровка: фиксированные слоты кадров + монтаж по говорящему (`assign_shots`) |
| баланс KIE | `utils/series_budget.check_balance` | до озвучки и платных кадров: баланс против оценки эпизода, не хватает — стоп (см. «Себестоимость») |
| `dialogue_voice` | `dialogue_voice.synthesize` | озвучка **первой** — до платных кадров |
| `scene_agent` ∥ музыка | `scene_agent.render`, `music_agent` | портрет клиента, кадры Nano Banana 2 с референсами, анимация Wan; трек по настроению |
| липсинк | `lipsync_agent` | Kling AI Avatar на ключевых репликах |
| `series_assembly` | `subtitle_agent.write_dialogue_ass`, `series_assembly.assemble` | субтитры по словам, монтаж |
| `series_qa` | `series_qa.check` | автопроверка ролика; брак голоса → одна переозвучка, иначе стоп |
| `quality_scorer`, `qa_agent` | | оценка кадров vision-моделью, ffprobe |
| очередь / `publisher_agent` | `anthology_agent.queue_episode` | `--prepare`, `--script`, `--resume` → очередь; иначе — сразу публикация |

### Кадры — `scene_agent`

Слоты (`anthology_agent.SLOTS`): `wide` (оба), `client_open`, `client_talk`, `client_turn`, `vera_listen`,
`vera_ask`, `detail`, `story`, `memory_1..3`. Лица держатся референсами в `image_input` Nano Banana 2: героиня —
`heroine.reference` (загружается в KIE, ссылка живёт 24 ч), клиент — портрет, сгенерированный в начале
эпизода. Оживляются только кадры без говорящих лиц: движущиеся губы не в такт речи заметны сразу.
Лица оживляет липсинк. Порядок оживления — `ANIMATE_ORDER = memory_1, memory_2, detail, memory_3, wide,
story`, из него берутся первые кадры, которые есть в эпизоде (`animated_key` + `animated_simple` штук).

**Сцены из жизни клиента** (`memory_1..3`, с 2026-10-23): пока клиент рассказывает, зритель видит саму
историю вне кабинета — место, событие, близкого человека. Раскадровщик даёт каждой сцене `setting_en`
(место и свет — подставляется вместо кабинета в `scene_agent._shot_prompt`), `with_client` (референс
клиента только если он в кадре) и `memory_lines` — реплики клиента под сцены. Не ставятся на первую и
последнюю реплику, поворот и деталь: там лицо и липсинк. Никто в сценах не говорит (со спины, в профиль,
руки), поэтому их можно оживлять Wan. Причина: в Studio зрители уходили в середине серии, где минуту
на экране был один кабинет. Цена — +3 кадра Nano Banana 2 (≈ $0.12); число оживлений не меняется.
Для сцен с `setting_en` из `style_en` убираются части про лампу, окно и кабинет (`scene_agent.scene_style`)
и добавляется светлый свет (`SCENE_LIGHT`); оптика, палитра и консистентность лиц остаются. Тёмные сцены
запрещены в промпте раскадровщика, а `anthology_agent.brighten` заменяет «Dimly lit», «at night» и т. п.
светлыми формулировками («dark» как цвет волос и одежды не трогается).

**Кадр-деталь** не встаёт на первую, последнюю реплику и поворот: при `detail_line` = 0, null или на них
он переезжает на следующую реплику клиента, по возможности не занятую сценой из жизни.

### Озвучка — `dialogue_voice`

- **Режим `dialogue`**: вся сцена одним запросом Gemini multi-speaker TTS (≤ 2 говорящих). Текст запроса —
  `tts_direction`, пустая строка, затем `Имя: [пометка] реплика`. Подряд идущие реплики одного героя
  склеиваются в один ход (`_turns`) — иначе модель путает голоса.
- **Пометки → только голос** (`_voice_cue`): из «глухо, глядя в пол» в TTS уходит «глухо»; действия
  («теребит ручку») выбрасываются — модель их читала вслух.
- **Тайминги**: Whisper (`base`) по готовой дорожке, слова выравниваются на текст сценария
  (`subtitle_agent._align_to_script`) → начало/конец каждой реплики и каждого слова.
- **Проверка дубля** (`_extra_speech`): ≥ 2 слов подряд, которых нет в сценарии (прочитанная пометка),
  — дубль не принят; до `DIALOGUE_TAKES = 3` дублей, потом озвучка по репликам (без эмоций).
- **Модели TTS** по очереди (у каждой своя дневная квота): `gemini-3.8-flash-tts`,
  `gemini-3.1-flash-tts-preview`, `gemini-2.5-flash-preview-tts`, `gemini-3.8-flash-lite-tts`
  (`GEMINI_TTS_MODEL` переопределяет). Голоса: Вера — Gacrux, клиентка — Leda, клиент — Orus.
- После первой реплики вставляется пауза «после холодного открытия» (0.7 с).
- **Темп** (`voice_tempo`, `apply_tempo`): готовая дорожка ускоряется `atempo` без смены высоты, тайминги
  реплик и слов делятся на темп. Сразу после озвучки — субтитры, липсинк и QA работают с ускоренной.
  Причина: Gemini читает диалог ~2 слова/с, а в YouTube Studio зрители уходили в середине (2026-10-23).

### Липсинк — `lipsync_agent`

`key_lines` выбирает первую реплику, реплику-поворот (`turn_line` из раскадровки) и последнюю
реплику персонажа — если их кадр с лицом. Кусок озвучки (реплика + 0.15 с) и кадр уходят в
`kling/ai-avatar-standard` (8 кр/с, ~2 мин на задачу), параллельно. Сбой → статичный кадр.
Задачи повторяются при 5xx/таймаутах до 2 раз (`kie_client.run_task(retries=2)`).

### Монтаж — `series_assembly`

- Таймлайн: кадр на каждую реплику, соседние одинаковые склеиваются, кадры < 1 с отдают время соседу.
- Статичный кадр — медленный зум (Ken Burns), клип — обрезка или замедление до ×1.2 и стоп-кадр;
  липсинк не замедляется.
- **Смена крупности** (`max_still`, `plan_pieces`): статичный отрезок длиннее `max_still` делится на равные
  куски; показы одного кадра чередуют полный кадр и наезд ×1.3 на зону лица (`FACE_Y = 0.38` высоты) —
  и внутри длинной реплики, и при возврате к кадру. Клипы и липсинк не режутся. Студия идёт без этого.
  Анимация, которой не хватает на отрезок даже с замедлением, доигрывается снимком этого кадра с наездом,
  а не стоп-кадром. Границы кусков стоят на сетке кадров по накопленному времени: при раздельном округлении
  24 куска серии 2 копили до 0.15 с сдвига картинки и липсинка от звука.
- Звук липсинка первой реплики режется с 0.0 — там же, где в монтаже стоит её кадр.
- **Звук сводится отдельным проходом** (`mix.wav`: loudnorm −16 LUFS + музыка с sidechain-компрессией),
  затем склеивается с видео и субтитрами. В одном графе с libx264 FFmpeg 9 молча терял ~3 с голоса.
- H.264 High@4.1, CRF 19, AAC 192k/48 кГц, `+faststart`. Размер кадра и логотип — параметры
  (используются Студией).

### Субтитры — `subtitle_agent.write_dialogue_ass`

Слова сценария по таймингам Whisper, по 2–3 слова, pop-анимация; цвет по роли; подпись говорящего над
субтитрами (при первом появлении — «Вера Соколова · психолог»); плашка сериала первые 3 с.

**Вопрос-крючок** (`hook_question`): под плашкой сериала с первой секунды висит вопрос о главной загадке
серии («Зачем он носит гантели в кофре?») — до начала реплики-поворота (`turn_line`), без неё — до конца.
Пишет его бесплатная модель (`anthology_agent.hook_question`, tier fast); отбраковка — длиннее 60 символов,
не вопрос, или ≥ 2 общих корня с поворотом (спойлер). Сбой → серия без плашки.
У «Кабинета 7» выключен: на пробной пересборке серии 2 автор оценил плашку как «ужасную» (2026-10-23).

### Автопроверка — `series_qa`

Без LLM, ≈ 10 с. Сравнивает готовый ролик с чистой озвучкой:

| Проверка | Брак |
|---|---|
| `sync` | голос ролика сдвинут относительно озвучки > 0.15 с (окна по 4 с; сдвиг подтверждён соседним окном или совпадение ≥ 0.7) |
| `speech` | реплика не слышна (Whisper по финальной дорожке, < 34 % слов) |
| `speaker` | реплика ближе по тембру (MFCC) к чужой роли |
| `subs` | у реплики нет субтитров, субтитры вне реплик или после конца ролика |
| `sound` | громкость вне −20…−12 LUFS, клиппинг, тишина > 2 с |
| `video` | чёрные кадры |
| `lipsync` | клип липсинка не на своей реплике |

Брак только голоса (`speech`/`speaker`) → одна переозвучка (`SERIES_QA_REVOICE`) и пересборка;
прочий брак → эпизод не попадает в очередь (запуск `failed`, видно в панели).

## Очередь и выпуск

Эпизоды — таблица `anthology_episodes` (`status`: `ready` → `published` | `rejected`).

```bash
py main.py --format series --series kabinet7 --niche "психология" --prepare 3     # собрать 3 в очередь
py main.py --format series --series kabinet7 --niche "психология" --publish-next  # выпустить самый ранний
py main.py --format series --series kabinet7 --niche "психология" --resume RUN_ID [--script FILE]
py scripts/series_queue.py [list | reject N | restore N]
```

- `--resume` доделывает упавший запуск: сценарий, раскадровка и оплаченные кадры берутся с диска;
  озвучка, липсинк и монтаж делаются заново. С `--script` — новая редакция реплик поверх готовых кадров.
- `--publish-next`: основная площадка через Zernio (`--platform`, аккаунт `ZERNIO_ACCOUNT_ID_<ID сериала>`),
  метки ИИ-контента (YouTube `containsSyntheticMedia`, TikTok `video_made_with_ai`), затем
  `also_publish`: `tiktok`/`instagram`/`youtube` через Zernio (`ZERNIO_ACCOUNT_ID_<ПЛОЩАДКА>`),
  `vk` — `vk_publisher` (video.save, нужен `VK_USER_TOKEN` с правом video); площадка без ключа
  пропускается. `manual_publish` (Wibes, VK Клипы) — одно сообщение в Telegram с роликом (≤ 49 МБ)
  и подписью для ручной загрузки.
- Ежедневный выпуск — `schedule` в конфиге + запущенный `scheduler.py` ([operations.md](operations.md)).

## Новый сериал

Панель → «Сериалы» → «Новый сериал»: технические поля копируются из `kabinet7`, история и героиня — свои.
Затем «Сгенерировать 3 варианта» портрета (`scripts/series_setup.py <id>` → `assets/series/<id>/candidates/`)
и выбор референса. Ограничения на сегодня: аккаунт публикации задаётся в `.env`
(`ZERNIO_ACCOUNT_ID_<ID>`), бриф сценариста частично заточен под жанр «специалист и клиент».

## Себестоимость (KIE, 200 кр = $1)

| Позиция | Кредиты |
|---|---|
| кадр Nano Banana 2 (1K) | 8 |
| анимация Wan 2.6 Flash, 5 с | 20 |
| липсинк Kling Avatar | 8 / с (реплика 5–8 с ≈ 40–64) |
| сценарий premium LLM | ≈ 1–3 |

Типичный эпизод: $0.8–1.7 (зависит от числа удачных липсинков). Финмодель — `docs/finmodel_kabinet7_v2.xlsx`.

**Проверка баланса до трат** (`utils/series_budget.py`, с 2026-10-23). Перед озвучкой и кадрами
`run_series_pipeline` сверяет `kie_client.balance()` с оценкой эпизода из конфига:
кадры (слотов раскадровки + 1 портрет) × $0.04 + `animated_simple` × $0.10 (Wan) + `animated_key` × $0.35
(Kling) + липсинк ≈ 15 с × $0.04 (если `lipsync_lines: "key"`), плюс запас 30 %. kabinet7 с 8 слотами ≈ $1.64.
При `--resume` с кадрами на диске считается только липсинк. Денег меньше — `BudgetError`: запуск
`failed`, Telegram-алерт «на KIE $… а эпизод ≈ $… — пополните баланс», платные шаги не начинались.
Баланс не узнать (сеть, KIE выключен) — предупреждение в логе, сборка идёт дальше.
